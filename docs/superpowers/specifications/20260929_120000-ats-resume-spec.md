## 2. ATS Readiness & Compliance Standards

To guarantee a >95% ATS parsing score across modern parsing algorithms (e.g. Sovren, Textkernel, Daxtra), the resume HTML and export formats must strictly follow ATS engineering rules:

| ATS Requirement | Implementation Standard | Anti-Pattern Avoided |
|---|---|---|
| **Document Structure** | Single-column, linear DOM flow from top to bottom. | No multi-column floats or nested tables that scramble reading order. |
| **Standard Section Headings** | Universal standard `<h2>` titles: `PROFESSIONAL SUMMARY`, `CORE TECHNICAL SKILLS`, `PROFESSIONAL EXPERIENCE`, `SELECTED PROJECTS`, `EDUCATION & CERTIFICATIONS`. | Avoid creative/unconventional headers like "What I Do" or "My Journey". |
| **Semantic Markup** | Clean HTML5 tags: `<header>`, `<main>`, `<section>`, `<h1>`, `<h2>`, `<h3>`, `<ul>`, `<li>`, `<p>`, `<time>`. | No canvas, images-as-text, SVGs for text, or obfuscated divs. |
| **Contact Data Layout** | Top header containing Name (`<h1>`), Target Title, City/State/Country, Phone, Email, Portfolio, GitHub, and LinkedIn links. | No contact information buried in headers/footers or columns. |
| **Job Entry Hierarchy** | Explicit structure per role: Role Title (`<h3>`), Company Name, Location, Date Range (`Month Year – Present / Month Year`). | Unclear dates or missing company identifiers. |
| **Bullet Point Format** | Standard bullet points using `<ul>` and `<li>`, starting with strong action verbs (Architected, Engineered, Reduced, Deployed, Led). | Avoid special character glyphs (✦, ➤, ➔) that decode as gibberish in raw text parsers. |
| **Text Extractability** | 100% selectable, copyable text. Include a "Copy Plaintext ATS Resume" button for instant pasting into job forms. | Scanned images or canvas-based renderers. |
| **Print & PDF Styling** | High-contrast black on white (`#111111` on `#FFFFFF`), system-safe fonts (Inter, Arial, sans-serif), 0.5-inch margins, `break-inside: avoid` on job entries. | Colors with poor contrast, background graphics, clipping margins. |

## 4. Technical Architecture & Component Design

### 4.1 Route & File Structure
```
pages/
  resume.vue                 # Dedicated ATS-compliant resume page route (/resume)
data/
  resume.ts                  # Fully typed static dataset for the resume
types/
  resume.ts                  # TypeScript types for resume sections, roles, skills
scripts/
  generate-pdf.mjs           # Node script using headless Chrome to render static PDF
public/
  jeric-izon-resume.pdf      # Pre-generated downloadable static PDF
```

### 4.2 Interactive Header & Utility Toolbar (Screen Only)
When viewed in a browser (`/resume`), a clean sticky/fixed toolbar provides:
1. **"Back to Portfolio"** (`NuxtLink to="/"`)
2. **"Download PDF"** (Triggers `window.print()` which opens native browser print dialogue configured with exact print CSS; also provides a direct link to static `/jeric-izon-resume.pdf`)
3. **"Copy ATS Plain Text"** (Copies clean, raw Markdown/plain-text formatted resume to the clipboard for fast job portal paste-in)
4. **"Print / Save as PDF"** button with quick instructions.

### 4.3 Print Styling (`@media print`)
- Hidden elements: Navbar, footer, toolbar buttons, background glows, decorative borders.
- Margin: `@page { size: letter; margin: 0.5in; }`
- Page Breaks:
  - `section { break-inside: auto; }`
  - `.resume-item { break-inside: avoid; page-break-inside: avoid; }`
  - `.section-heading { break-after: avoid; page-break-after: avoid; }`
- Colors: Pure white background `#FFFFFF`, deep charcoal/black text `#111111` for crisp printer output and high OCR readability.
- Typography: System sans-serif / Inter font stack, 10pt base font for compact, balanced multi-page flow.

### 4.4 Automated PDF Generation Script
- Script: `scripts/generate-pdf.mjs`
- Engine: Uses local Chrome (`/usr/bin/google-chrome`) via headless CLI flags:
  `google-chrome --headless --disable-gpu --print-to-pdf=public/jeric-izon-resume.pdf --no-pdf-header-footer ...`
- Integrated into `package.json`: `"generate:pdf": "node scripts/generate-pdf.mjs"`

## 6. Boundaries

- **Always Do:**
  - Maintain 100% semantic single-column HTML order for ATS parsers.
  - Test print preview and ensure no orphan headings or awkward bullet point cuts across pages.
  - Keep text extractable and selectable.
  - Preserve zero em-dashes rule (use standard hyphens `-` or commas per repo style).
- **Ask First:**
  - Adding third-party PDF rendering libraries (e.g. jspdf, html2pdf.js) if native print-to-pdf and headless Chrome suffice.
  - Modifying top-level layout components beyond adding links to the new resume page.
- **Never Do:**
  - Never commit directly to `main` without following git safety rules.
  - Never launch background dev servers or watch processes.
  - Never render resume content as canvas, SVG text, or layout tables.
